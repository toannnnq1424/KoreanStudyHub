# Practice authoring — source-of-truth audit (2026-08-08)

Phạm vi là toàn bộ surface biên soạn Practice của lecturer: owner-only dashboard/draft/publish, revision/governance, import Excel/Text/PDF/candidate, material, objective explanation, và Speaking prompt. Mọi route lecturer dưới đây có `Roles.PREAUTH_LECTURER`, trừ endpoint content material chỉ yêu cầu authenticated nhưng tự kiểm quyền theo asset/reference. Line number là source tại thời điểm audit, không phải API contract độc lập.

| UI action → HTTP | Controller → service/external/repository | State/result and downstream UI |
|---|---|---|

Response has `contentDigest`, not `candidateDigest`; JS only trusts `reviewUrl` then navigates. |
| Create Text/PDF candidate → `POST /pdf-authoring/candidates` multipart | `PracticePdfImportApiController.createBasicCandidate:70–126` → exact target → `PracticePdfAiPayloadBuilder` → `PracticePdfAiOrchestrator.generate:58–84` → structured provider/control plane → `PracticePdfAuthoringCandidateAssembler:41–62` | no PDF object/session; strict output becomes candidate. 200 response uses `candidateDigest`; invalid request 400, candidate semantic 422, AI capability/binding 503, unexpected 500. UI shows error or redirects review. Provider call is request-local/synchronous. |
| Candidate initial/load → `GET /authoring-candidates/{id}` then `GET /{id}/data` | `PracticeAuthoringCandidateReviewController.page:53–64`, `data:66–77` → `PracticeAuthoringCandidateService.get:200–206` → `PracticeAuthoringCandidateRepository` | page performs owner + draft READ checks; data returns canonical `CandidateView` with `version` and `contentDigest`. 403 body is normalized. |
| Save review → `POST /{id}/review` | controller `updateReview:79–105` → `PracticeAuthoringCandidateService.updateReview:209–249` | verifies owner/edit/version/digest, normalizes/validates and replaces candidate content/digest; state becomes `REVIEWING`; JPA lock conflict 409. |
| Ready / reject / learner preview → `POST /{id}/ready|reject|learner-preview` | controller `markReady:107–130`, `reject:132–155`, `learnerPreview:157–178` → candidate service / `PracticeAuthoringCandidatePreviewService` | Ready requires no blockers and same actor acknowledgement for warnings, state `READY_TO_APPLY`; reject `REJECTED`; preview is no-write learner DTO. Candidate expiration can turn nonterminal state into `EXPIRED`. |
| Apply → `POST /{id}/apply` incl. UUID `applyRequestId` | controller `apply:180–222` → `PracticeAuthoringCandidateApplyService.apply:81–209` → candidate/draft `find...ForUpdate`, apply-event repository | candidate lock then draft lock; replay is idempotent. Ready+digest+base draft version must match; append/normalize/validate/material-authorize, save draft, save apply event, `APPLIED` in one transaction. 200 `DRAFT_APPLIED` + `editorUrl`; conflicts 409; rejects 422. |

Candidate persistent transitions are `PARSED → NORMALIZED → VALIDATED → REVIEWING → READY_TO_APPLY → APPLIED`, or `REVIEWING → REJECTED`; due nonterminal becomes `EXPIRED`. `FAILED` exists in entity for creation failure but a failed provider request is not a persisted candidate in the request-local controller path. `candidateVersion` is a changing JPA lock version: never hard-code it as zero.

| Action → HTTP | Controller/service/external/storage | Persistent state + UI behavior |
|---|---|---|
| Read current explanation → `GET /api/.../current` | `PracticeExplanationController.current:79–88` → `ObjectiveExplanationEditorialService.current:118–144` → revision repository | validates revision against live draft authority; empty optional is 404/204 to editor, which renders “no draft”. |
| Generate → `POST /api/.../generate` | controller `generateDraft:67–77` → editorial service `generateDraft:104–116` → `ReadingListeningExplanationClient` → structured AI binding `PRACTICE_RL_EXPLANATION` | provider call is synchronous although response is 202; saved revision invalidates prior effective revision. UI receives `EditorialView`, no poll job. |
| Edit/approve → `PUT /revisions`, `POST /revisions/{id}/approve` | controller `saveEditedDraft:90–109`, `approve:111–122` → editorial service `147–198` → `PracticeExplanationEditorialRevisionRepository` | edit validates strict typed JSON and creates fresh unapproved revision; approve needs PUBLISH and current fingerprint. Publisher calls `requireApprovedForPublish`, then promotes valid approved output to immutable question-version artifact after publication. |
| Read/save mode → `GET` / `PUT` speaking-prompt base | `SpeakingPromptAuthoringController.get:62–68`, `save:102–135` → state/authoring services → source/artifact/task repositories | source and draft expected revisions guard concurrent writes. Manual text save changes source/options and supersedes stale TTS; mode save does not enqueue AI. |
| Upload original audio → `POST .../audio` multipart | controller `upload:137–156` → coordinator → `SpeakingPromptAssetService.uploadOriginal` (private staged object + ffprobe/hash) → authoring bind/enqueue | backend rechecks authority before I/O and under binding lock; active original material reference + STT artifact/task state update. 202 state; JS polls base GET. |
| Retry/confirm STT → `POST .../transcription/retry`, `PUT .../transcription` | controller `158–197` → authoring retry / `SpeakingPromptTranscriptService.revise:34–104` | retry returns 202 queued/active, 200 needs-review, 429 with `Retry-After`, or 409 not-retryable. Confirmation persists a transcript revision and source pointer; transcript remains evaluator context, not learner delivery. |
| Request/serve TTS → `POST .../tts`, `GET .../media/{origin}` | controller `199–233`, `70–100` → authoring service/task worker → TTS port/provider; state service private storage read | fingerprint match may return 200 reusable ready; pending returns 202. Worker binds generated audio only if source still current. Media is private no-store; not a public object URL. |
| Unlink original audio → `DELETE .../audio` | controller `235–250` → authoring service `592–624` → material unlink + lifecycle queue if unreferenced | unlinks reference, supersedes/cancels detached STT path, bumps source state; returns replacement editor state. |

Speaking worker (`SpeakingPromptAiTaskWorker`/processor) owns external STT/TTS execution and durable task/artifact progress. The authoring request never exposes provider credentials or direct storage keys. Publication (`SpeakingPromptPublicationService.prepare`) blocks publish unless the selected delivery, current artifact(s), source hash and required confirmed STT context satisfy its contract.

Remaining documentation gap now explicitly covered here: the difference between MVC material catalog and editor asset API, each initial read, fallback GET semantics, controller-level response codes/redirects, and the concrete database/lifecycle transitions at each authoring mutation.
